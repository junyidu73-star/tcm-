# 知衡 · 医学机制发现工作台

本地运行的医学机制研究工作台，包含账号登录门禁、模型 API 后端代理、研究助手、PubMed 检索和疾病驱动多源探索流程。

## 启动与登录

Windows PowerShell 在本目录运行：

```powershell
python server.py
```

直接运行默认端口为 <http://127.0.0.1:8765>；交付启动脚本设置为 <http://127.0.0.1:8766>。**当前代码需要 CPython 3.13**：研究引擎入口依赖 `research_engine.recovered.pyc`，其字节码版本与 Python 3.13 匹配。首次启动前安装 `requirements.txt` 中依赖。首次访问会跳转到登录页；首次使用可选择“创建账号”，设置 3–64 位账号和至少 10 位密码，并完成图形验证码。账号及 PBKDF2 密码哈希保存在本目录 `users.sqlite3`。登录 Cookie、会话和模型 API Key 仅在后端进程内存中；退出登录会清理该会话的 API 配置，停止服务会清理所有会话。

## GitHub 上传与部署入口

本项目的 **GitHub 仓库根目录**应当是本目录，即包含 `server.py`、`requirements.txt`、`index.html`、`research_engine.py` 和 `research_engine.recovered.pyc` 的目录。不要把工作区最外层的 `outputs/`、zip 包、其他项目目录或运行数据一并上传。`.gitignore` 已排除用户数据库、运行结果、日志、虚拟环境和缓存。API Key、邀请码、微信密钥及真实患者数据不得提交。

**ColoCrossing Ubuntu VPS 部署时，主程序入口选 `server.py`，部署脚本是 `deploy_ubuntu.sh`。**不要在 Streamlit Cloud 的 “Main file path” 中选 `server.py`：本项目是标准库 HTTP 服务，不是 Streamlit 应用；Streamlit 会把它当成页面脚本，不能按本项目架构提供登录网站。

部署前须在 VPS 上只读检查当前系统、VPN、端口、Nginx 和防火墙。现有安装脚本面向 Ubuntu 22.04，并要求管理员权限；它现在会检查 Python 3.13 是否已安装，不会自行添加第三方软件源。服务器须先准备 CPython 3.13，然后从 GitHub 克隆本仓库，在项目根目录按 [Ubuntu部署说明.md](Ubuntu部署说明.md) 执行部署。应用仍由 systemd 运行 `server.py`，Nginx 提供 HTTPS；不要把 8765 直接开放到公网。

**源码完整性说明：**研究引擎主体目前保存在 `research_engine.recovered.pyc`，仓库需要包含该文件才能导入研究模块，但它不是可读源码，并且绑定 CPython 3.13。GitHub Pages、Streamlit Cloud 均不是本平台的合适部署目标。计划长期公开维护前，应将该引擎恢复为可读的 `research_engine.py` 源码，再删除此字节码依赖；在此之前，不要把仓库宣传成完全可复现的开源研究引擎。

验证码为后端生成的一次性图形挑战，并有按 IP 的尝试频率限制。账号密码登录当前没有找回密码流程；请妥善保管账号密码。

## 微信扫码登录

微信登录遵循微信开放平台网站应用扫码授权流程，需要已审核通过的网站应用及授权登录能力。服务端环境变量配置：

- `WECHAT_APP_ID`
- `WECHAT_APP_SECRET`
- `WECHAT_REDIRECT_URI`（必须是已在微信开放平台配置的 HTTPS 回调地址，例如 `https://your-domain.example/api/auth/wechat/callback`）

本机 `127.0.0.1` HTTP 演示不能完成微信真实 OAuth 回调；没有这些配置时，微信按钮会显示未启用。上线需要公网 HTTPS 域名、合规网站应用审核和反向代理。微信授权通过 `state` 随机值校验，应用密钥只存在服务端环境变量，不写入页面。

## Ubuntu 22.04 小范围团队部署

发布包包含 `deploy_ubuntu.sh` 和 [Ubuntu部署说明.md](Ubuntu部署说明.md)，适用于通过 Nginx/HTTPS 向课题组成员提供访问。部署脚本使用邀请码限制注册，应用仍只绑定 `127.0.0.1`，不要直接开放 8765 端口。反向代理会按真实客户端 IP 执行注册/登录限流。公网部署前请先确认域名指向 VPS，并在云防火墙开放 80/443；SSH 端口保持可访问。

部署服务使用 `ZHIHENG_HTTPS=1` 和 `ZHIHENG_INVITE_CODE`。登录会话及模型 API Key 仍仅驻留服务进程内存；重启服务会要求重新登录并重新填写 API Key。用户账号数据库在 `users.sqlite3`，需纳入备份。

## 工作台功能

- **疾病基因找药独立页面**：只输入疾病名称；上游疾病靶点、多队列代理证据及可分析组学差异基因汇总为候选基因，按直接性和重复证据排序，再按基因查询 [DGIdb 药物—基因互作 API](https://dgidb.org/api)，并与原 [ChEMBL 药物机制数据服务](https://chembl.gitbook.io/chembl-interface-documentation/web-services/chembl-data-web-services)记录合并。中药支路用合格疾病基因反查 HERB 2.0 的药材、方剂与成分靶点，在独立栏展示共享基因与 HERB 来源；方剂/药材的基因重合不等于疗效，也不混入西药候选表。逐条保留基因证据范围、数据库来源和 PMID；代理表型与精确表型不混写。数据库互作仅是已登记关系，不表示该药对目标疾病有效，更不是临床处方。上游数据库超时会有限重试并单独标记失败，不清空其他来源结果。
- **科研算法运行台独立页面/服务**：侧边栏链接到独立 FastAPI 应用，不与研究助手、疾病发现表单重复。首版只有审核过的 NumPy/Pandas 描述统计算法，支持 CSV/合成样例、后台任务、状态、日志和结果下载；不运行用户脚本。代码及 VPS 只读审查报告位于工作区的 `outputs/科研算法在线平台/`。尚未部署到云服务器。

- 研究助手支持 OpenAI 兼容接口、OpenAI Responses、Anthropic Messages、Gemini、Azure OpenAI、Ollama 和自定义 OpenAI 兼容协议。
- 模型密钥从浏览器提交到同源后端，只驻留进程内存；“连接测试”会真实请求所选模型。
- API 出站请求默认直连，不继承失效的系统代理设置；如果网络必须通过代理，请在启动服务前设置 `ZHIHENG_USE_SYSTEM_PROXY=1`。连接测试会区分 HTTP 401/403/404/429、DNS、TLS、超时和代理错误，不记录或回显 API Key。DeepSeek 有独立预设，使用官方 Base URL 和当前模型 ID。
- API 连接测试有按登录会话计算的每分钟请求上限；测试失败后请先根据显示的 HTTP/网络错误修正配置，不要连续重复点测。新版把连接测试和正常聊天分开限流，并明确显示测试限额。
- PubMed E-utilities 与 Europe PMC 文献检索、完整分页、PMID/DOI去重及摘要筛选；PubMed超大结果集按发表日期拆分，Europe PMC使用游标。报告命中数、取回数和分支完整性。当前尚未接入中文付费数据库或全文筛查工作流；可选设置 `NCBI_EMAIL`、`NCBI_API_KEY`。
- 研究助手中的“疾病驱动发现”只要求输入疾病名称；后台检索PubMed、GEO、BioStudies/ArrayExpress、PRIDE、Open Targets、GDC（肿瘤）及ChEMBL等来源，并在数据设计通过审核时尝试小规模探索统计。摘要中可提取经引文核对的中药干预线索，仍需全文与药材/方剂核实。具体范围、限制和可复制提示词见 [运行提示词.md](运行提示词.md)。
- 若GEO矩阵通过审核并产生显著差异基因，报告提供按比较方向标注的上下调基因列表下载及HERB 2.0入口，可把签名交给HERB Analyze与真实中药/成分/方剂实验签名做连接匹配。该步骤需研究者手动完成；平台不会把文献提到的药名当成连接预测结果。
- HERB 2.0 现有只读连接器：按精确疾病实体读取药材、成分、方剂关联及 P/FDR；这些关联是 HERB 的共享靶点统计推断，单独作为数据库先验展示，不能当成本平台从输入组学签名算出的预测分数。HERB 条目会写入证据关系表并保留来源ID、关联方法和证据类型。
- GEO、BioStudies/ArrayExpress、PRIDE按疾病同义词分页检索并保留不确定记录；逐项目列出发现的公开文件、样本入口和错误。目录不代表文件已下载或数据已分析，SRA/ENA的原始文件尚未自动枚举或下载。E-GEOD链接GEO，防止当作独立队列；miRNA/circRNA/lncRNA等非编码RNA数据不会进入mRNA差异分析。
- 疾病队列按直接表型、相关代理表型和未确认范围分别显示。符合条件的相关 GEO 队列可走独立分析支路；代理结果与目标疾病差异基因、靶点和药物排序隔离，并需独立验证。队列的物种、组织、分组、数据类型及比较范围均逐项审核。
- 摘要筛选会校验每批 PMID 完整性和引文原文；格式错误或批次缺项时自动缩小批次重试。仍失败的记录标为技术失败并列入报告，任务只显示部分完成，不计作“待核实”。
- PubMed EFetch 会识别期刊论文和书籍章节，并对批次漏回的 PMID 单条重试；仍缺失时报告缺失数与 PMID。
- 助手生成步骤只允许跳转工作台已知研究页面，不执行模型生成的代码或命令。

## 数据库优先模块边界

- 疾病组学分析读取 GEO/ArrayExpress 等数据库实际表达矩阵；摘要文献只进入证据/约束支路。每项结果保留队列设计和比较方向。
- 自有扰动连接预测单独使用疾病差异签名与**实测**中药/成分/方剂扰动签名计算反向 Spearman 连接。没有足够共享基因、物种/组织不适配或缺少剂量/时间信息时返回不评分；不会用文献提及药名或 HERB 的共享靶点 P 值冒充连接分数。
- 文献科学约束模块有独立 claim 格式和训练准备门槛：每条主张需保留 PMID、原句、关系方向、物种、组织/细胞、剂量、时间和检测方法；支持、反证与不确定标签需人工核验后才可训练。摘要筛选决定不直接作训练标签。
- 本地开发使用 SQLite 证据关系适配器和内容哈希文件存储；[postgres_schema.sql](postgres_schema.sql) 提供 PostgreSQL 部署表结构。对象存储可设置 `ZHIHENG_OBJECT_BUCKET` 使用 S3 兼容存储；凭证由环境或密钥管理提供。当前网页服务仍是轻量本地后端，FastAPI/Streamlit、Nextflow/MLflow、GEARS、DoWhy 和 PySB 尚未作为默认运行依赖。
- 单细胞/多组学模型、跨组织扰动预测和动力学模拟需各自适用的数据集及验证；平台不把 GEARS 对单基因 Perturb-seq 的预测外推到复方或 bulk RNA-seq。

## 安全边界

- 服务默认仅绑定 `127.0.0.1`，不带对外开放的管理权限或账号恢复功能；不要直接将端口暴露到公网。
- 部署到公网前必须有 HTTPS 反向代理，并将 `ZHIHENG_HTTPS=1` 设为 Secure Cookie；同时完成安全审查、备份策略、账号恢复、隐私政策和访问日志治理。
- 不要把 `WECHAT_APP_SECRET`、模型 API Key 写入代码仓库。应通过服务进程环境变量或部署平台的密钥管理注入。
- 注册账号数据保存在 `users.sqlite3`；会话、聊天和模型密钥不写入该数据库。

## 科研功能边界

项目概览和部分候选排序仍含演示数据，不是已训练或临床验证的模型。疾病驱动分析当前仅有少量特定矩阵适配器及通用审核分析器，结果需正式流程和独立验证。HERB 的关联 API 已接入，但本平台自有扰动连接结果只会在实测签名下载、映射和组织/物种/剂量/时间条件审核通过后生成。科学约束模型目前未训练；已定义证据输入与金标准门槛。真实使用需要导入有许可的数据、扩充人工核验训练集并做独立验证。模型回答和文献摘要须核对原文，不构成临床建议。

## 研究工具页面更新（2026-11-02）

- **文献检索与筛选**：用户用自然语言描述目标文献；已配置模型据此生成可复制的严格提示词、PubMed 检索式和筛选方案。检索由 PubMed E-utilities 实际执行，单次可设 100–10,000 条上限，并展示数据库总命中、实际取回数和完整性。结果可人工标为纳入/排除/待核实并导出 CSV 供 ASReview LAB 导入。当前页面只实际检索 PubMed；跨库去重、全文筛选、双人裁决尚未在该页面实现。
- **Meta 分析**：同一主后端接收已核对的研究级 CSV，支持 yi+SE/方差、连续结局两臂汇总数据或二分类事件数据；提供 DerSimonian–Laird 随机效应汇总、Q/I²/τ²、预设亚组、亚组间 Q、逐项剔除敏感性分析、高偏倚风险研究排除分析，以及研究数达到10项时的 Egger 小研究效应检查。亚组由研究者依据预设临床/生物学因素选择，不根据 I² 自动试分组。当前是轻量实现，不包含完整 REML/Hartung–Knapp、多层依赖效应、网络/诊断 Meta、全文自动提取或正式风险偏倚评估；置信区间和预测区间用正态近似，正式发表前需统计人员复核。
- **实验复核与算法改进**：上传去标识化 CSV 后检查数值字段、缺失、组别和样本 ID 等基础结构，生成排查清单和未验证约束草案；可以让已配置模型依据数据摘要拟定 PubMed 检索式，再实际查询并导出题录。页面尚未训练神经符号/注意力模型，不会自动改写或覆盖既有算法；研究者需核实规则、反证和适用域，并通过独立队列/实验验证后才能实现算法更新。
- **AI 页面同步**：疾病发现任务进度及报告会同步显示在研究助手页面；文献、Meta 分析和实验复核结果各自在独立页面呈现，同属一个登录和主后端。
- **GitHub 项目评估**：目前没有确认一个成熟开源项目能够可靠地一站式覆盖多库检索、全文筛选、自动提取、Meta 分析、异质性处理、偏倚分析及可复现报告。推荐模块化组合：ASReview 负责人工在环的主动学习题录/摘要排序；正式 Meta 统计引擎后续可采用 R 的 `metafor` 或 `meta`；MAVIS 虽提供较早的 Shiny GUI，但年代较久，不作为当前核心依赖。当前页面的轻量统计实现不等同于 `metafor`/`meta` 的完整方法集。
